# 首次烧录后闪灯、屏幕无背光

2026-10-09，用户分别烧录四个镜像并断电重启后，绿色/紫色灯持续闪烁，屏幕无背光。

## 已确认的原因

QSPI 初始化把 PF10 时钟引脚与 PF8/PF9 数据引脚合并配置为 AF10。实际映射是 PF10/CLK 使用 AF9，PF8/IO0 和 PF9/IO1 使用 AF10。PF10 的 AF10 是 SAI4_D3，所以外部 Flash 没有获得 QSPI 时钟，Bootloader 无法读取 JEDEC ID，在启动屏幕之前进入错误循环。

依据：用户提供的板卡 HAL 例程 `Drivers/BSP/QSPI/qspi.h`，以及 [ST STM32H747XI 数据手册](https://www.st.com/resource/en/datasheet/stm32h747xi.pdf) 的 GPIO 复用表。

修复前通过 STM32CubeProgrammer 2.6.0、ST-LINK Hot Plug 实际读取：

| 读取项 | 结果 | 含义 |
|---|---|---|
| GPIOF_AFRH，0x58021424 | 0x00000AAA | PF8/9/10 都是 AF10；PF10 错误 |
| CM7 VTOR，0xE000ED08 | 0x08000000 | 仍在 Bootloader 向量表，未进入应用 |
| CM7 镜像信息，0x08020400 | 43414249 / 07470101 / 00010000 / 00000007 | CM7 镜像信息存在于规定地址 |
| CM4 镜像信息，0x08120400 | 43414249 / 07470101 / 00010000 / 00000004 | CM4 镜像信息存在于规定地址 |

原始读取日志保存在 `build/black-screen-diagnosis/before-registers.log`。以上操作只有读取，没有下载固件、写寄存器、擦除 Flash 或修改选项字节。读取镜像头只能确认头部与位置，不能代替整个镜像的写后校验。

## 已修正并重新生成

- `APP/QSPI/bsp_qspi.c`：PF6/PF7/PF10 使用 AF9；PF8/PF9 和 PG6 使用 AF10。
- Bootloader 与 CM7 应用共同使用这个驱动，因此两个目标都已重新编译。四目标均 0 错误、0 警告。
- 已更新 `build/FACTORY.hex`、各目标 HEX/BIN、`UPDATE.BIN` 和 `manifest.json`。修复前的合并固件与受影响目标备份在 `build/black-screen-diagnosis/`。
- 增加启动阶段、QSPI 初始化返回值和 JEDEC ID 的 Keil Watch 变量。

## 如果仍停在 Bootloader

在 Keil 中选择 `Cabinet_Bootloader` 目标，加载同一次编译的调试符号，在错误循环暂停并观察以下变量。调试暂停应冻结 IWDG1，避免看门狗在查看期间重启。

| 变量 | 含义 |
|---|---|
| `cabinet_boot_stage` | 1 进入；2 等 CM4；3 系统时钟；4 QSPI；5 镜像/元数据；6 跳应用；0xE1 QSPI 失败；0xE2 镜像/元数据失败 |
| `cabinet_boot_result` | 当前失败步骤的返回值，0 表示该步骤成功 |
| `bsp_qspi_init_status` | 0 成功；-1 时钟源；-2 HAL 初始化；-3 Flash 复位命令；-4 JEDEC 读取；-5 ID 不匹配；-6 状态寄存器读取 |
| `bsp_qspi_jedec_id` | 读出的三字节 ID，W25Q256JV 通常为 0xEF4019 |
| `bsp_qspi_status3` | Flash 状态寄存器 3；低位 ADS 表示当前地址模式，位 1 ADP 表示上电地址模式 |

修复后 GPIOF_AFRH 的低 12 位应为 0x9AA。进入 CM7 应用后 VTOR 应为 0x08020000；此时 Bootloader 的 RAM 变量可能已被应用覆盖，不能再用旧变量地址推断启动结果。

## 第二次黑屏：地址模式不一致

用户重烧后，实板读数已变成 PF10/AF9、JEDEC ID=0xEF4019、QSPI 初始化返回 0，但启动阶段为 0xE2。回读完整内部 Flash 并比较后，四个目标全部与对应的最新 BIN 一致。备份位于 `build/black-screen-diagnosis/second/internal-flash.bin`（2 MiB）。

继续通过只读 SPI 命令得到 SR1=0x00、SR2=0x02、SR3=0x63。SR3 的 ADS=1、ADP=1，表示当前及上电均为四字节地址模式。板卡的“实验23 QSPI FLASH实验”中 `norflash_init()` 会把 ADP 非易失位写为 1；66h/99h 软件复位后仍按该非易失配置恢复四字节模式。此前驱动却发送三字节地址，导致启动记录无法正确保存/校验。

已改为 W25Q256JV 专用四字节命令：读 0x0C、页编程 0x12、4 KiB 擦除 0x21、64 KiB 擦除 0xDC，地址长度固定为 32 位。这组命令在 ADS=0 或 1 时都采用四字节地址。驱动不会改写 ADP、QE 或保护状态位；Flash 分区不变。

依据是用户提供的 `4. 芯片资料/W25Q256JV.pdf`：6.1.4、7.1.6、指令表，以及四字节读/写/擦除章节。新增 `tests/test_qspi.c` 直接测试实际 BSP 和启动记录代码，覆盖 ADP=0/1；旧驱动在同一测试中的记录保存断言失败，新驱动通过。完整主机回归及四目标编译再次通过。

读 SR1/SR2/SR3 时曾短暂停核，通过 QSPI 外设寄存器发出只读命令，然后恢复运行；没有执行外部 Flash 的编程/擦除命令。日志中对 FCR 写 1 清标志后出现的 `Failed to download data` 是旧版 CubeProgrammer 将自清除寄存器按普通内存读回校验导致，不能当成 Flash 被写保护的证据。
