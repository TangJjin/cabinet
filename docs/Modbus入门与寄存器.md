# Modbus RTU 入门与温湿度采集

当前仅保留 CM4 通过 USART6 + RS485 作为 Modbus RTU 主站读取温湿度。CM7 负责界面、报警、日志和离线升级；参数通过屏幕修改，再经 OpenAMP 同步给 CM4。

## 概念与参考寄存器

USART6 负责串行字节收发，RS485 收发器负责转换成 A/B 差分信号，Modbus RTU 规定字节格式、地址、功能和 CRC。传感器厂商定义实际寄存器表和数值倍率。

| 参数 | 当前参考定义 |
|---|---|
| 参考传感器 | Seeed S-TH-01，实物型号变化时核对说明书 |
| 串口 | 9600、8N1 |
| 设备地址 | 默认 1，可在屏幕设置 |
| 功能码 | 03，读保持寄存器 |
| 寄存器 0 | 有符号温度，除以 100 得到 ℃ |
| 寄存器 1 | 无符号湿度，除以 100 得到 %RH |
| 请求周期 | 约 1 秒，模拟模式不发真实请求 |
| RS485 引脚 | PG14 TX、PG9 RX、PG12 高发送低接收 |

## 一帧请求与响应


默认发送：

```text
01 03 00 00 00 02 C4 0B
地址 功能 起始地址 数量 CRC低字节 CRC高字节
```

预期响应共 9 字节：`地址 03 04 温度高 温度低 湿度高 湿度低 CRC低 CRC高`。

UART 通过 DMA2 Stream0 循环接收，IDLE/错误中断发送任务通知。任务读取 DMA 剩余计数判断新数据，检测到至少 5 ms 安静时间后封帧，校验地址、长度、功能码、CRC、数值范围。9600、8N1 的一个字符约 1.04 ms，因此 5 ms 大于 3.5 个字符时间。异常帧、超长帧和超时均计一次失败，不把缓冲区内容直接当测量值。

源码建议顺序：`cabinet_rtu_request` → `poll_sensor` → `HAL_UARTEx_RxEventCallback` → `cabinet_rtu_decode` → `sensor_task` → `bsp_ipc_send`。

[Modbus 官方规范入口](https://www.modbus.org/modbus-specifications)

当前编解码是针对固定温湿度读取操作的实现，异常响应按采集失败处理；5 ms 无新增数据是当前实现的简化封帧方式，不包含完整通用 RTU 状态机的所有时序检查。

成功结果更新 CM4 的 sample，再通过 OpenAMP 进入 CM7 的 model.sample。连续三轮失败标记离线，下一秒继续尝试。水浸检测另走 GPIO，不经过温湿度 Modbus 链路。

接线、电平和供电见 [接线与资源分配](接线与资源分配.md)。
